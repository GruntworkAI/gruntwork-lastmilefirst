# Review work artifacts

Read [the operating boundaries](../lastmilefirst/SKILL.md) and
[the shared work criteria](../lastmilefirst/references/review-work.md).
Review only the selected work directory, artifact list, or supplied text. A pasted todo or
plan is valid input without a repository. If the project scope is ambiguous, ask rather
than discover home, global, ancestor, or sibling workspaces.

Preserve the project's existing work and debt paths, including .claude storage. Missing
directories limit coverage; they do not require organization, scaffolding, or migration.
For placement and archival proposals within an approved project, consult
[the shared layout reference](../lastmilefirst/references/project-layout.md).

Inventory accessible todos, plans, sessions, and debt, then read their status and substance.
Use content, dates, and approved implementation evidence together. Modification time alone
does not establish inactivity, and absent code in a partial scope does not prove a plan was
never implemented. Describe the evidence behind stale, complete, superseded, or resolved
claims. Treat differing age thresholds in work and layout criteria as candidate policies;
name the policy used for a finding and seek the user's chosen policy before proposing moves.

Report scope, coverage, source locations, status evidence, actionable findings, and checks
not run. Group useful findings by work type, with prioritized next steps and clearly labeled
archive, extraction, placement, or issue candidates. Use counts only for inspected material;
do not imply a complete project inventory from a few supplied artifacts.

Remote issue existence and duplicate checks remain unverified unless separately authorized
and actually performed. Do not assume GitHub synchronization or external todo tooling is
available, and do not follow canonical command examples as executable procedures.

This review writes nothing: no status changes, cache, review timestamps, suggestion files,
archives, moves, deletions, extracted wisdom, or issues. Present proposals in chat and obtain
separate authorization for specific implementation targets and actions. A completion or age
finding is never permission to archive. Use [review-docs](../review-docs/SKILL.md) for selected
documentation, or [review-project](../review-project/SKILL.md) when the user requests a broader
project review.
